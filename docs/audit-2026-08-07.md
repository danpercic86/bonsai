## 1. Executive summary — top issues by severity

1. **CRLF check-in filters bypassed by partial staging and staged-only stash** (Rust core) —
   files staged/stashed with raw CRLF bytes under `core.autocrlf=true`; whole-file phantom
   diffs and conflict-prone stash applies. (§2.1, §2.2)
2. **Settings load–modify–save races across concurrent writers** — lost updates incl. the
   persisted MCP token/port, silently breaking the user's `claude mcp add` registration. (§2.3)
3. **Commit file-browser/scope reset keyed on row index** — any background refetch that
   shifts rows closes the commit browser the user is reading. (§2.4)
4. **Update controller has no state guard between check and download** — allows overwriting
   live download progress and starting a second concurrent `downloadAndInstallUpdate`. (§2.5)
5. **`git log` option injection via `scope_ref`** in search (defense-in-depth: a leading-dash
   value becomes a `git log` option, e.g. `--output=<file>` = arbitrary file write). (§2.6)
6. **`claude` binary resolution fails for the npm `.cmd` shim on Windows** — every AI feature
   errors `AiUnavailable` on an npm-only install; plus timeout-kill orphans the node child. (§2.7)
7. **No CI at all** — the ~1030 tests (Rust + frontend) gate nothing on push/PR; only a
   tag-triggered release workflow exists. (§5)
8. **Tauri command layer largely untested** — 15+ command domains have zero tests; frontend has
   zero component/e2e tests. (§4)
9. **Untracked-clobber guard missing on bisect/rebase restore paths** — `bisect_reset` /
   interactive-rebase finish/abort can silently overwrite an untracked file. (§3.1)
10. **MCP server races** — double-start on enable, and an ephemeral-port fallback that keeps
    the old bearer token while another local process can squat the old port. (§3.2)

## 2. Confirmed bugs (MUST-FIX class)

### 2.1 Partial staging bypasses check-in filters — `crates/bonsai-core/src/git/stage_partial.rs:187,232`
`Direction::Stage` reads raw workdir bytes (`fs::read`) and writes them to the index via
`add_frombuffer` without running the check-in (CRLF/ident) filter. With `core.autocrlf=true`
(Git-for-Windows default; settable from Bonsai's own config editor), a partial stage writes
CRLF content against an LF index/HEAD: every selected line shows as changed and the file
appears perma-dirty. The no-op comparison at :210 is affected the same way.
**Fix:** filter the buffer (git2 filter list / `blob_path` semantics) before `add_frombuffer`.

### 2.2 Staged-only stash folds unfiltered worktree bytes — `crates/bonsai-core/src/git/stash.rs:266-268`
`create_staged_stash` does `repo.blob(fs::read(abs))`, embedding raw CRLF content in the stash
tree. Applying the stash later rewrites whole files and conflicts with unrelated edits.
Same root cause as 2.1. **Fix:** use `Repository::blob_path` (applies check-in filters).

### 2.3 Settings read-modify-write races — `src-tauri/src/settings.rs:394` + callers
`save_to` is an atomic rename, but nothing serializes the load→mutate→save cycles running
concurrently on different blocking threads: `set_ui_settings` (commands/ui_settings.rs:180-182),
`set_session` (:252-255), the recents hook in `open_repo` (commands/repo.rs:79),
`remove_recent_repo` (repo.rs:162), and MCP persistence (mcp.rs:196,429,459). Whichever rename
lands last silently reverts the other's fields. Worst case: enabling MCP persists
`mcp_token`/`mcp_port` concurrently with a pane-width drag save — the token write is lost and
the next launch generates a fresh token, breaking the registered `claude mcp add`. Both writers
also share the fixed `settings.json.tmp` name (settings.rs:402-408), so a concurrent pair can
surface a spurious `Io` error. **Fix:** one process-wide mutex (or actor) around load→mutate→save.

### 2.4 Commit browser closes on any row shift — `src/components/RepoWorkspace.tsx:1001-1004`
The commit-diff effect (:963-969) deliberately preserves the panel when a refetch merely shifts
the selected commit's row (`commitDiffKeyRef` on OID), but the scope-reset effect depends on
`selectedIndex` (a number). Any watcher tick / auto-fetch that inserts or removes a row above
the selection remaps the index and closes the open commit file browser + resets scope mid-browse.
**Fix:** key the reset effect on the selected commit's OID (and `compare?.oid`), not the index.

### 2.5 Update controller: no check/download state guard — `src/hooks/useUpdateController.ts:56-93`
`check()` is callable while `status === 'downloading'` (Settings → "Check for updates" is always
enabled): a not-available result nulls `infoRef` and flips state to `upToDate`, wiping live
progress while the download continues; an available result re-shows "Download & install",
allowing a second concurrent `downloadAndInstallUpdate` (`pendingUpdate` in ipc/tauri.ts:95-97
is never consumed; the mock's `mockUpdateReady` likewise stays set). **Fix:** bail out of
`check()` while downloading and out of `download()` unless status is `available`/`error`.

### 2.6 `git log` option injection via `scope_ref` — `crates/bonsai-core/src/git/search.rs:220-230`
`scope_ref` is pushed as a bare argv token before `--` in Path mode and as a positional in
Content mode. A leading-dash value (e.g. `--output=C:/…/startup.bat`) becomes a `git log`
option — an arbitrary-file-write primitive. Not reachable from repo data today (git refuses ref
names starting with `-`; the value comes from the app's own sidebar), but it converts any
IPC-level compromise into file write and falsifies the module's stated injection-safety
invariant (:203-204). **Fix:** reject a leading `-`, or pre-validate via `revparse_single`, or
emit `--end-of-options` before it.

### 2.7 AI CLI spawn: Windows `.cmd` shim not resolved; timeout orphans children — `crates/bonsai-core/src/ai/mod.rs:200-202,166-171`
`Command::new("claude")` does not resolve the npm `claude.cmd` shim on Windows (CreateProcess
only finds `.exe`), despite the comment at :198-199 claiming it does — on an npm-only install
every AI feature fails `AiUnavailable("not found")`. `external.rs:105-125` already has a correct
PATHEXT-aware `resolve_program`; reuse it. Related: on timeout, `child.kill()` kills only the
`cmd.exe` shim; the node process behind it keeps running (kill the process tree). *(structural
for the timeout half)*

### 2.8 Raw NUL byte embedded in source — `src/components/repoWorkspace/useCommitSearch.ts:30`
`queryKey()` joins fields with a literal U+0000 byte in the file (verified with `od`). The file
is treated as binary by grep/ripgrep (it silently drops out of content searches, including this
audit's until spotted) and is fragile to editors/formatters, which may strip the byte and
silently change the delimiter. **Fix:** write `'\0'` (byte-identical at runtime). Related NIT:
`searchHelpers` `queryKey` variant joins with a plain space (collision-prone).

## 3. Risky patterns / latent issues (SHOULD-FIX class)

### Rust core (git)
- **3.1 Untracked-clobber guard inconsistent** — forward force-checkouts are guarded
  (`bisect.rs:201`, `rebase_interactive.rs:319` via `ensure_no_untracked_collision`), but the
  restore/abort paths are not: `bisect.rs:510-512` (`restore_to_original`),
  `rebase_interactive.rs:534-536` (finish) and :649-651 (abort). A file generated during a
  bisect test run can be silently overwritten by `bisect_reset`. Violates the shared-guard
  policy from commit 46a34d4.
- **3.2 Checkout-level `GIT_ECONFLICT` reports `Conflicts { paths: [] }`** —
  `stash.rs:560-563` (+ :654-656, :692-694; `autostash.rs:119-121`): when apply fails at
  checkout (dirty file in the way), the index has no conflict entries, so the UI says
  "conflicts" with no paths. Map to a checkout-conflict error carrying libgit2's message.
- **3.3 `collect_file_diff` merges multiple deltas into one `FileDiff`** — `diff.rs:251-284`:
  no per-delta finalize; if the pathspec matches two deltas (rename pairing failed), the second
  `file_cb` overwrites path/status while both deltas' hunks accumulate. Guard on a second call.
- **3.4 Mutex-poison `expect` inside the libgit2 credentials callback** —
  `cred_cache.rs:305,312`: one panic while holding the lock permanently kills all fetch/pull/push
  (panic inside a C-callback trampoline) until restart. Poison is benign here; recover with
  `into_inner()`.
- **3.5 No other-worktree check on `checkout_branch`/`checkout_remote`** — only
  `checkout_branch_autostash` (branches.rs:421) refuses a branch checked out in another
  worktree; `checkout_branch` (:328) and `checkout_remote` (:604, `set_head` at :683) don't,
  so two worktrees can end up on the same branch (git itself refuses this).

### Rust app layer (src-tauri)
- **3.6 MCP double-start race** — `mcp.rs:163-171` + auto-start (lib.rs:51-58): the
  "already running" check releases the lock before `start()` inserts `McpRunning` (:441-443);
  two racers both bind and both persist token/port; the persisted pair may belong to the dead
  instance. Fix: async "starting" guard around the whole enable path.
- **3.7 Ephemeral-port fallback keeps the old bearer token** — `mcp.rs:275-293` falls back to
  port 0 while `start` reuses the persisted token: a local process squatting the *old* persisted
  port (which the user's `claude mcp add` still targets) receives the real bearer token and can
  replay it against the new port. Rotate the token when the bound port differs from the
  persisted one.
- **3.8 Inconsistent poison policy on `AppState.repos`** — `commands/shared.rs:74-77` and
  repo.rs lock sites turn a poisoned map into a permanent error for every command, and the
  scheduler silently skips all ticks (scheduler.rs:553-556) — while the scheduler's own locks
  deliberately recover. One panic under the lock bricks the session.

### Frontend
- **3.9 `refetchCompare` treats any rejection as "commit gone"** — `RepoWorkspace.tsx:605-609`:
  a transient failure (index lock, IO hiccup) tears down compare mode with a misleading toast.
  Distinguish the not-found error kind.
- **3.10 Double refetch storm per mutation** — every mutation runs `refreshAll` (~9 parallel
  fetches) and the watcher-debounced `repo-changed` for the same writes re-runs the identical
  9 ~300 ms later, per open tab (RepoWorkspace.tsx:871-905, 1008-1046). Add self-event
  suppression/coalescing. *(structural)*
- **3.11 Esc closes every stacked global overlay at once** — `App.tsx:814-829`: no layering /
  early return between onboarding/health/aiAssets/settings/shortcuts. Close topmost only.
- **3.12 Mock persistence: `profiles` taken unvalidated** — `mock/persistence.ts:263-265`
  passes corrupt array elements straight into Settings state (unlike `readRecents`' per-element
  filter). Mock-only, but it's the harness's persistence contract.
- **3.13 Ctrl+R/F5 not suppressed under confirm dialogs** — `useWorkspaceKeyboard.ts:184-188`
  honors only `globalModalOpen`; a refresh under a pending hunk-discard confirm makes the
  confirmed action a silent no-op (stale guard returns undefined, RepoWorkspace.tsx:1428).
  *(structural)*
- **3.14 Unhandled promise rejections** — `App.tsx:294` (`removeRecentRepo(...).then` inside a
  catch block, no rejection handler; also uses `setRecents` while the dep array lists
  `refreshRecents`), `App.tsx:550-560/:579-582` (`pickFolder()` rejections escape),
  `ConflictEditor.tsx:426` (`loadLanguageExtension` failure), `RepoWorkspace.tsx:1030/1072/1148`
  (`void subscribe()` — a rejected event registration silently loses live refresh).

### Rust core (non-git)
- **3.15 Unbounded revwalk in AI explain range digest** — `ai_explain.rs:432-441`
  (`resolve_digest_range`, BetweenRefs/SinceCommit): materializes every commit in the range in
  memory before the 200-line meta cap; no `MAX_COMMITS`-style bound (contrast
  `ai_branch_name.rs:158-177`, which caps at 50 + counts overflow).
- **3.16 One corrupt commit aborts an entire search** — `search.rs:334-340` (`revwalk_search`
  uses `?` per commit); `health.rs:240` deliberately degrades per-commit for exactly this
  reason. Skip-and-continue.
