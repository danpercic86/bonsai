## 1. Placement (D2) — header-toolbar entry + modal dialog

**Decision:** a **Dependencies** icon button in the header toolbar opens a **modal dialog**
(`dialog-overlay` + `dialog-card`, the `RepoHealthPanel` / `AiAssetsPanel` shape). The toolbar icon
carries a **vulnerability count chip** — the only out-of-dialog summary signal.

| Option | Verdict |
|---|---|
| Right-panel no-selection section | **Rejected.** 380px cannot hold name + installed + latest + kind + advisory; the no-selection state is the staging surface the user works in all day, so a security list either pushes Changes down or gets buried under it. It would also enter the `--rp-*` density scope for a list that is read occasionally. |
| Own view (graph replacement / 4th pane) | **Rejected.** Bonsai has no view switcher; adding one is new top-level chrome for a read-occasionally report. |
| **Toolbar entry → dialog** | **Chosen.** Precedent is exact (Health, AI Assets: repo-scoped, opened on demand, a 720–880px card). One 32px icon is the whole chrome cost. It is visible while the tracker is off, which gives AC1's consent surface an entry point. Vulnerabilities — the only item that needs to reach the user unprompted — surface as a count chip on the icon. Updates do not: they are routine and would turn the chip into noise. |

**Toolbar order (updates §1):** theme · list view · AI assets · health · **dependencies** · dev ·
settings · identity. It renders only when `activeRepo !== null`, like its two repo-scoped neighbours.
**Density:** the dialog and toolbar are app chrome, so both are **density-invariant** (§3). There is
one geometry for `cozy` and `compact`, and no `data-density` scope.

## 3. Toolbar entry — `DepsToolbarButton`

- **Base:** `.btn-icon deps-toggle`, 32×32, with the `DependenciesIcon` glyph.
- **With vulnerabilities** (`enabled && report && summary.vulnerable > 0`): the button becomes
  `width: auto; padding: 0 6px 0 4px; gap: 4px; display: inline-flex`, and shows the icon plus
  `.deps-count-chip`.
  - Chip: `height: 16px; padding: 0 5px; border-radius: 999px; font: 600 11px/14px var(--font-ui);
    font-variant-numeric: tabular-nums; color: var(--text-1);`
    `background: color-mix(in srgb, var(--danger) 14%, transparent);`
    `border: 1px solid color-mix(in srgb, var(--danger) 40%, transparent);`
  - Content: `⊘` (`aria-hidden`, `color: var(--danger)`) + a thin space + the count. The count is
    capped at `99+`.
  - The whole chip is `aria-hidden`; the count lives in the button's `aria-label`.
- **Re-check cue** (a check is running and a report exists): the chip gets the §11 P123 recipe —
  `aria-busy="true"` on the button, `outline: 1px dashed currentColor; outline-offset: -1px` on the
  chip, no motion. The button never spins (§8: only toolbar Refresh may spin). With no chip there is
  no running cue on the toolbar; the dialog shows it.
- **Stale, offline and error** get no toolbar signal. They are not threats, and the dialog explains
  them.
- **States:** hover `background: var(--bg-2)` (the `.btn-icon` default). `:focus-visible` gets a 2px
  `--accent` ring at 1px offset. Pressed: none beyond `.btn-icon`. No disabled state — the button is
  absent when no repo is open.

| State | `aria-label` | `title` |
|---|---|---|
| off | `Dependencies` | `Dependencies — off` |
| enabled, no report yet | `Dependencies` | `Dependencies — checking…` |
| report, 0 vulnerable | `Dependencies` | `Dependencies — {U} updates · checked {age}` (`No updates` when U = 0) |
| report, N vulnerable | `Dependencies, {N} vulnerable` | `Dependencies — {N} vulnerable, {U} updates · checked {age}` |
| + running | append `, checking again` | append ` — checking again…` |

`U = major + minor + patch`. Use `update` / `vulnerable` singular when the count is 1.

**Contrast** (computed 2026-09-28, chip tint composited over `--bg-1`):
- `--text-1` count: **11.6:1** dark, **12.6:1** light.
- `⊘` in `--danger`: **3.8:1** dark, **3.8:1** light. It is a graphics glyph, and the 3:1 bar is met.
- The 40% border is decoration only (§11).

## 4. Dialog anatomy

### 4.1 Header — `DepsHeader`

- The title `Dependencies` uses `.dialog-title shortcut-title` inside `.shortcut-header`, like Health.
  The card has `role="dialog" aria-modal="true" aria-labelledby` pointing at the title.
- Right cluster (`.asset-header-actions`, gap 8), in this order:
  1. **Caption** (`.health-caption`, 12px `--text-2`, nowrap):
     - With a report: `checked {age}`.
     - While running: `checked {age} · Checking… {done} of {total}` when `total > 0`, otherwise
       `Checking…`.
     - The caption's `title` is the absolute local date and time: `Checked {toLocaleString()}`.
  2. **`stale` pill** (hueless §11 recipe) when `manifestsChanged || lastError` and a report exists.
     `title`: `These results may be out of date.`
  3. **Check now** (`.btn-secondary`). While running it is disabled and reads `Checking…`. It is
     absent when the tracker is off.
  4. **Close ×** (`.btn-icon shortcut-close`, `aria-label="Close"`).
- **Live region:** `<p class="sr-only" role="status" aria-live="polite">`. It is permanently mounted
  and holds text only on these transitions:
  - start: `Checking dependencies…`
  - finish: `Dependency check finished: {N} vulnerable, {U} updates.`
  - failure: the notice's first sentence.

  Progress counts are **never** announced (§11: a live label must tick no faster than about once a
  second).

### 4.2 Summary and filter bar — `DepsSummaryBar`

The summary **is** the filter bar. Each count is a toggle, so the counts and the filters cannot
disagree, and no separate summary row is needed.

- Toggles use the `.search-toggle` recipe (26px tall, `aria-pressed`, `.is-active` = 22% accent tint +
  `--accent` border). Each toggle adds `min-height: 26px`, so it clears the 24px floor.
  - `Vulnerable {N}`: the label, then the count in a hueless §11 pill. When N > 0 the toggle adds a
    leading `⊘` (`aria-hidden`, `--danger`), and that toggle is the leftmost, most prominent item.
    When N = 0 it is shown as `Vulnerable 0` and is **disabled**.
  - `Major {n}` / `Minor {n}` / `Patch {n}`: independent toggles. A toggle whose count is 0 is
    disabled.
- **Filter semantics** (pure, in `depsView.filterRows`; order is never changed — §5.2 of the
  architect contract):
  - Kind toggles form a set; an empty set means "any kind".
  - `Vulnerable` narrows to `vulns.length > 0`.
  - Both narrow together (AND).
  - Any active toggle hides rows that have neither `update` nor `vulns`: local, private, unknown and
    up-to-date rows.
  - The name filter is a case-insensitive substring match on `name`.
  - A group with zero matching rows is hidden. `notTracked` and `parseError` groups are **always
    shown**, so the report never looks complete when it isn't.
- **Name filter:** the existing `ListFilterInput` with
  `aria-label="Filter packages by name"`, placeholder `Filter packages…`, width 200. It is included
  because repos with hundreds of packages need it, and it reuses an existing control.
- **Secondary line** (12px `--text-2`, one line, ellipsis): the non-zero counts from `upToDate`,
  `private`, `local`, `unknown`, `notTracked` and `parseErrors`, joined by ` · ` (§8.4 strings).
  It is omitted when all are zero.
- **When filters hide everything:** the list shows `No packages match these filters.` and a
  `Clear filters` `.btn-link`.

### 4.3 Column header and groups — `DepsGroup`

- **Sticky column header:** one row above the list, `position: sticky; top: 0`,
  `background: var(--bg-1)`, section-label style (11px, uppercase, `letter-spacing: 0.08em`,
  `--text-2` — not `--text-3`, because these labels are read). It is `aria-hidden`; each group table
  carries its own visually hidden `<thead>` with the same labels.
- **Columns:** `table-layout: fixed`.
  - Package: remainder, min 200.
  - Installed: 112.
  - Latest: 112.
  - Update: 72.
  - Vulnerability: 208.
  - Actions: 32.
  - Every cell has `padding: 0 8px` and is ellipsized on one line. **List rows never wrap.**
- **Group header:** 32px. It is an `<h3>` containing a `<button aria-expanded aria-controls>` —
  the disclosure. Groups are expanded by default, and the expanded state is kept per `manifestPath`
  for the dialog's lifetime.
  - Content: chevron `▾`/`▸` (`aria-hidden`); `manifestPath` in mono 12px `--text-1`; ` · ` then the
    ecosystem label (§8.4) in `--text-2`; ` · ` then `lockfilePath` in mono 12px `--text-2` when
    present.
  - Right-aligned `--text-2` 12px: `{n} packages` and, when present, ` · {v} vulnerable`.
  - Hover: `--bg-2`. The path takes priority: the lockfile and ecosystem segments shrink first
    (`flex-shrink` 2 vs 1), then the path end-ellipsizes. `title` = the full
    `manifestPath · ecosystem · lockfilePath`. Use no `direction: rtl` trick and no invisible bidi
    codepoints (§0).
  - The ecosystem is stated once per group, not per row, because every row in a group shares it.
    Each row's accessible name repeats it (§5.2).
- Each group's `<table>` has `aria-labelledby` pointing at the header button.
- **Group-state lines** sit under the header. Each is 12px `--text-2`, `padding: 4px 8px 4px 28px`
  (aligned with the name column), wraps normally (prose, not a list row) and keeps `max-width` in
  `ch`:
  - `noLockfile`: §8.3 string. It sits above the rows.
  - `parseError`: the group has no table. It shows one line, the §8.3 string with `{file}`; the
    backend `message` is shown only as the line's `title`. The ecosystem chevron is omitted because
    there is nothing to expand.
  - `notTracked`: the group has no header button and no table, just one 32px line: `{manifestPath}`
    (mono) + ` — {label} isn't tracked yet` (`--text-2`).
  - **All rows private or local** (derived: every row's availability is `private` or `local`, and
    n ≥ 1): the §8.3 "company registry" lead (or its `{host}` / config-unreadable variant) sits
    above the rows. This makes the Q2 ruling read as intentional rather than broken. The
    report-wide config-unreadable lead (§8.3) suppresses these group leads.
- **Scale:** D3 limits transitive rows to vulnerable ones, so the realistic worst case is hundreds
  of direct rows across workspace members, not thousands. Rules:
  - Each group renders its first **200** rows, then a `.btn-link` row `Show all {n} packages`.
    Rust's order puts the least important rows last, so the cut hides nothing urgent. The expansion
    is kept per group.
  - Filters apply before the cap.
  - No virtualization library is added. Row height is a fixed 32px and the tables are plain DOM.
  - If a measured view ever exceeds about 2,000 rendered rows, revisit together with the architect's
    ~2 MB channel note (architect §8). Frame timing is a **USER CHECKPOINT** item.

### 4.4 Row anatomy — `DepsRow` (32px, `border-top: 1px solid var(--border)` between rows)

| Cell | Checked (direct) | Transitive (vulnerable or not verified) | Unknown | Local / private |
|---|---|---|---|---|
| Package | `name` 13px `--text-1` + tags | same + `transitive` tag | same | same |
| Installed | `current ?? declared`, mono 12px `--text-1` | `current` | same | `current ?? declared` |
| Latest | `latest`, mono 12px — `--text-1` when `update`, `--text-2` when equal | empty | `colSpan 2` → `AvailabilityCell` | `colSpan 3` → `AvailabilityCell` |
| Update | `UpdateKindPill` or empty | empty | (spanned) | (spanned) |
| Vulnerability | see below | see below | see below (†) | (spanned) |

† An `unknown` row is a deps.dev 404 or, from P125h, an oversize deps.dev answer
(`reason: 'tooLarge'`), but OSV is still queried for any public row that has a
resolved version (architect §5.1 step 5). So an unknown row **can carry vulns**, and it keeps its
own Vulnerability cell. Local and private rows are never queried, so their span covers it.
| Actions | registry ↗ button | registry ↗ | registry ↗ | **none** (no URL — §7.6) |

- **Tags** (`RowTag`, hueless §11 pills, lowercase, placed after the name, gap 4, `flex: none`):
  - `transitive` when `relation === 'transitive'`.
  - The scope word (`dev` / `build` / `optional` / `peer`) when `scope !== 'normal'`. This only ever
    appears on direct rows: Rust emits transitive rows with `normal` scope, so the two tags never
    combine.
  - At most two tags. The **name** is what ellipsizes; the tags never do. The name's `title` is the
    full name.
- **Vulnerability cell:**
  - When `vulns.length > 0`: `SeverityPill(vulns[0].severity)`, then `vulns[0].id` in mono 12px
    `--text-1` (ellipsized), then `+{n−1}` as a hueless pill when there is more than one advisory.
  - When `vulnsChecked && vulns.length === 0`: empty. An empty cell means "checked, none known".
  - When `!vulnsChecked` and `vulns.length === 0`: the hueless `not verified` pill with the §8.3
    cause `title`. This applies to every such row: no-lockfile ranges, NuGet unconfirmed casing, an
    all-malformed OSV answer, and any future cause. An unverified row is never rendered like a clean
    one.
  - **Combined case (P125h)** — `!vulnsChecked` **and** `vulns.length > 0`. This is what a
    `responseTooLarge` row always is (Rust keeps a placeholder advisory for the oversize record) and
    what a partially malformed row is (the readable advisories survive). The cell shows
    `SeverityPill` · id · `+{n−1}` (if any) · the hueless `not verified` pill, gap 4.
    - The pills are `flex: none`; **only the id ellipsizes**, down to nothing if it has to. The
      cell `title` is `{id} · {§8.3 not-verified title}` so the full id is always one hover away.
    - `.sr-only` suffix: `, vulnerabilities not verified` (same as the empty case).
    - The expanded details row ends with the §8.3 **incomplete-list note** (see `DepsAdvisoryList`
      below).
    - Rows are expandable because they have vulns. The placeholder advisory renders like any
      advisory with no record (`unrated`, `No summary provided.`). The wire has no per-advisory
      too-large flag, so the UI **does not guess** which advisory is the placeholder. It states
      the problem once, at row level (§11.5).
  - **Transitive not-verified row (R2, ruled 2026-09-29):** a transitive row whose OSV hits were all
    malformed has `vulns: []` and `vulnsUnverified: 'malformedAdvisory'`. It shows the `transitive`
    tag, an empty Latest cell and the `not verified` pill. It is **not expandable** (no vulns, no
    chevron), so its reason is in the pill `title` only. It does not count toward `Vulnerable {N}`
    or the group's `{v} vulnerable`. Like any row without `update` or `vulns`, it is hidden while a
    filter toggle is active (§4.2). That is intended, not a bug: the unfiltered list and the
    up-to-date line's `Some weren't checked` suffix still surface it.
- **Expansion:** only rows with vulns are expandable. The Package cell holds a
  `<button class="deps-row-toggle" aria-expanded aria-controls={detailsId}>` wrapping the name and a
  chevron. Rows without vulns render the name as plain text, with no chevron.
- **Details row** (`DepsAdvisoryList`, one `<tr>` with a single `colSpan` cell,
  `padding: 8px 8px 8px 28px`, `background: var(--bg-0)`): one block per advisory, gap 8.
  - Line 1: `SeverityPill` · `id` (mono 12px `--text-1`) · the CVSS score when present
    (`CVSS 9.8`, `--text-2`) · aliases (mono 12px `--text-2`, comma-separated, ellipsized; `title` =
    all of them).
  - Line 2: `summary`, 12px `--text-1`, wrapping allowed, max 3 lines with `-webkit-line-clamp`.
    `title` = the full summary. When there is no summary: `No summary provided.` in `--text-2`.
  - Line 3: an `Open advisory` `.btn-link` with `aria-label="Open advisory {id}"`.
  - **Incomplete-list note (P125h):** when `row.vulnsUnverified` is non-null, one final block
    follows the last advisory: the hueless `not verified` pill, gap 8, then the §8.3
    incomplete-list string for that reason in 12px `--text-2` (wraps; prose). It is plain text,
    not a `role="status"`, because it is static content read in order. There is no action.
- **Row actions:** the registry button is `.btn-icon deps-row-action`, **24×24** (§3.1 floor — not
  the 20px `.row-action`), `ExternalLinkIcon`, `--text-2`. It is always visible rather than
  hover-revealed, so keyboard and pointer users see the same row.
  - `aria-label` / `title`: `Open {name} on {host}` (§8.4 hosts).
- **Row states:**
  - Hover: `background: var(--bg-2)`.
  - An expanded row's `<tr>`: `background: var(--selection)`. `--text-1` on `--selection` is
    9.4 / 13.3 (§6.3). The pills remain legible; their inks are all `--text-1` / `--text-2`.
  - Focus: the ring is on the focused button only (2px `--accent`, 1px offset, `:focus-visible`).
- **React key:** `depsView.rowKey(row) = relation + '\u0000' + name + '\u0000' + (current ?? declared ?? '')`.
  It is scoped inside the group keyed by `manifestPath`. No id is needed from the DTO.

### 4.5 Pills — `DepsPills.tsx` (existing hues only; label is always the word)

| Kind | Recipe | Label |
|---|---|---|
| severity critical | **Solid** §11 P102: `background: var(--danger); color: var(--danger-text)` (4.80 / 4.93, measured) | `critical` |
| severity high | Verdict: `--text-1` label, `⊘` glyph in `--danger` (`aria-hidden`), 14% danger tint, 40% border | `high` |
| severity medium | Verdict: `⚠` in `--warning`, 14% warning tint | `medium` |
| severity low | Verdict: `⚠` in `--warning`, 14% warning tint | `low` |
| severity unknown | Hueless (`--text-2` on its 12% tint, 5.79 / 6.22) | `unrated` |
| update major | Accent tint: `--text-1` over `color-mix(--accent 15%)` (the `.asset-chip-canonical` recipe) — **10.9:1 dark / 12.7:1 light** on `--bg-1` | `major` |
| update minor / patch | Hueless | `minor` / `patch` |
| availability | Hueless + reason text (12px `--text-2`) | `local` / `private — not checked` / `unknown` |

Rules and rationale:
- Critical and high differ in **shape** (solid vs tint) as well as label.
- Medium and low share a hue and differ by label. Red and yellow are reserved for vulnerabilities.
  An update is a fact, not a threat, so only `major` gets emphasis, and that emphasis comes from the
  accent.
- A verdict Bonsai could not compute uses the hueless style (§11 "Unknown is hueless"). That is why
  unscored severity is labelled `unrated` — so it does not collide with the `unknown` availability
  word.
- Contrast, computed 2026-09-28 over each 14% tint composited on `--bg-1` (dark / light):
  - `--text-1` labels: danger 11.6 / 12.6, warning 10.5 / 12.9.
  - Glyphs: `⊘` in `--danger` 3.8 / 3.8; `⚠` in `--warning` 5.6 / 3.8.
  - Both glyphs clear the 3:1 graphics bar, and the `⚠` figures agree with §11's 5.64 / 3.80.
  - On a `--bg-2` hovered row every figure drops by less than 0.5 and stays above its bar.
- Pills follow §11 geometry: 11px, `1px 6px`, radius 8, transparent border on hueless pills.
- A severity pill inside a row is `role="img"`-free, because its label is already the word (§11).

## 5. Interaction, keyboard, accessibility

### 5.1 Open and close
- Openers: the toolbar button and the palette `Dependencies` entry.
- Initial focus lands on the **card** (`tabIndex={-1}`), so Enter triggers nothing by accident.
- Focus is trapped by `useDialogFocus` and restored to the opener on close.
- **Esc** is layered: it first clears a non-empty name filter (the `ListFilterInput` capture idiom),
  then closes the dialog. Enter never closes it.
- `Ctrl/Cmd+F` inside the dialog focuses the name filter and prevents the graph search from
  opening.
- A mouse-down on the backdrop closes the dialog, as Health does.

### 5.2 Tab order and names
Tab order: Check now → Close → notice action (if any) → Vulnerable → Major → Minor → Patch → name
filter → for each group, the header button, then per row the row toggle (if any) and the registry

tabindex. The filters make long Tab runs avoidable, and the tables keep SR table navigation working.

  `{name}, {severity} vulnerability {id}` plus `, and {n−1} more` when applicable. `aria-expanded`
  carries the state.
- Each row's first cell holds an `.sr-only` suffix giving the ecosystem and the tags, for example
  `npm, transitive`.
- The `AvailabilityCell` reason text is visible, so SR users read it too. There is no title-only
  meaning.

1. `Open on {host}` — omitted for local/private rows.
2. `Open advisory {id}` — one per advisory, at most 5; after that, `Show all {n} advisories`, which

4. `Copy name`.

## 6. States (AC13) — which body renders, and what the notice says

Derived by `deriveState(view)` in the new pure module `src/components/deps/depsView.ts`, which P125g
creates. It applies the architect's §2.3 rules. The shipped `useDepTracker` hook (P125f) returns
only `{ view, progress, refresh }` and derives nothing, so wherever the architect's §2.3 says
"computed in the hook", read "computed in `depsView.ts`". Exactly **one** body and **at most one**
state notice are shown (plus the link note, see below).

| State | Condition | Body | Notice |
|---|---|---|---|
| off | `!enabled` | `DepsOffBody` (§8.1) | — |
| loading | `!report && !lastError` | `DepsLoadingBody`: summary bar skeleton + 3 skeleton groups × 4 `.skeleton-row` (`--bg-2` bars) | — |
| failed, no report | `!report && lastError` | `DepsFailedBody`: title + reason + `Try again` (§8.3 per kind) | — |
| empty | `report.groups.length === 0` | `DepsEmptyBody` | stale / failure notice if applicable |
| up to date | report, `major+minor+patch+vulnerable === 0` | calm line (§8.3) above the normal list | as below |
| populated | otherwise | list | as below |
| + stale | `manifestsChanged && !lastError` | (unchanged) | stale notice |
| + offline / service with report | `lastError && report` | (unchanged) | failure notice with age |
| + link failure | `openUrl` rejected | (unchanged) | link note, **in addition** to any state notice and placed below it. It is the only case with two notes. |

- **Notice recipe (`.deps-notice`):** the same declarations as `.settings-row-note--warn` —
  a 12% `--warning` tint, a `box-shadow: inset 3px 0 0 var(--warning)` bar, `--text-1` 12px text,
  `padding: 6px 8px 6px 12px`, radius 4, `margin: 0 0 8px`.
  - Re-measured over `--bg-1`: text **10.9:1 dark / 13.3:1 light**.
  - A trailing action `.btn-link` (`Check now`) is part of the stale and failure notices only.
  - The link note follows §12.14 "an inline note is not a toast": no ×, no timer. It clears when the
    next link open begins, and when the dialog closes.
  - The notice is `role="status"`, not `alert`: nothing was lost, and the spec says "non-alarming".
  - **Never `--danger`, never a modal.**
- **Why no-report failures use the pane empty-state block instead of the §8 danger banner:** the
  user lost nothing and cannot fix a remote service, and danger hue is reserved for loss. The block
  (title 13px/600 `--text-1`, reason 12px `--text-2`, one `.btn-secondary` action) is §8's
  "empty state names the fix" shape.
- **Empty** is the one exception to "names the fix": there is nothing for the user to fix, so it has
  a title and a reason and **no** action. Check now stays available in the header.
- **Running with a report:** the previous results stay fully interactive (AC10). The header caption
  shows progress. The list does **not** get `aria-busy`, because it would hide still-valid results
  from some screen readers.
- `CheckFailure.message` is never shown as primary copy. It goes in the notice's `title` only as
  `Details: {message}`, and the failure body's reason line is chosen by `kind` (§8.3).

  in success tone: `Dependency checks are off. Saved results were deleted.`
  - It sits **beside** the row's help, not instead of it.
  - The switch's `aria-describedby` composes `{help-id} {note-id}`.
  - The element is always mounted and empty while idle.
  - The group's single `sr-only role="status"` announcer carries the same text, cleared when the
    toggle starts.
  - Turning back on clears the note.
- **Footer link in the dialog:** `Dependency check settings` closes the dialog, then calls
  `openSettingsAt('general')` with the group scrolled into view. Only one modal is ever open.
  - **Amended 2026-09-29 (ratifies `8b09665`):** both openers — this footer link and

    - When off, Space opens the consent dialog and does not flip the switch.
    - When on, Space turns checks off without a confirmation and deletes saved results. That is
      the same as a click (§7 "Turning off"): results rebuild on the next check, and the outcome

  - Whether the switch paints its `:focus-visible` ring after a **mouse** click on the link
    (programmatic focus) depends on the WebView's heuristic. It is a **USER CHECKPOINT** in the
