## 1. Tags rollup: a re-check keeps the verdict pill

### 1.1 Problem

`TagSyncRollup.tsx:21` computes `busy = useTagSyncChecking() || state === 'checking'`, so every
forced re-check (focus rescan, auto-fetch, manual refresh) swaps `⚠ N` → `checking…` → `⚠ N`
on the Tags header. The pill changes width twice per re-check and reports "we don't know" about
a verdict we already hold. P121e made the section body keep its verdict through a re-check; the
header pill is the only surface still flipping.

### 1.2 Rule (applies to the one header pill, collapsed **and** expanded, since the
`SectionHeader` `extra` slot renders in both states — `TagsSection.tsx:194,200`)

| Settled state (`tagSyncState`) | In flight? | Pill |
|---|---|---|
| `idle` | no | none |
| `checking` (first check, no verdict yet) | yes | hueless `checking…` (unchanged) |
| `ready`, divergences `N > 0` | no | `⚠ N` warn pill (unchanged) |
| `ready`, `N > 0` | **yes (re-check)** | **same `⚠ N` warn pill + re-check cue (§1.3)** |
| `ready`, `N = 0` | yes or no | none (a clean re-check stays badge-less, no `checking…`) |
| `unavailable` | yes or no | none (count is 0; §2.3 quiet degrade, offline note in the body is the only signal) |

`checking…` therefore appears only when there is no settled result at all. `unavailable` counts as
settled (it is P121e's settled lifecycle — `TagsSection.tsx:118`).

### 1.3 The re-check cue

On the existing `.branch-badge.submodule-badge-warn` span, nothing about label, glyph, hue, padding
or size changes. Add:

- `aria-busy="true"`
- a static dashed inner outline (CSS below)
- the re-check `title` and `aria-label` (§1.5)

```css
/* src/styles/sidebar.css, directly after the .submodule-badge-warn rule (~L206) */
.submodule-badge-warn[aria-busy='true'] {
  outline: 1px dashed currentColor;
  outline-offset: -1px;
}
```

- **Zero layout.** An outline takes no box space. `-1px` offset lays the dashes exactly over the
  existing 1px 40% border ring, so the pill stays **19.94 px** tall and keeps its width. It follows
  `border-radius: 8px` in WebView2 and WebKit ≥16.4.
- **Why a shape, not a colour.** Dashed vs solid perimeter reads as "provisional" without any hue
  shift, so it doesn't rely on colour alone. It can't be confused with the focus ring, which is a
  2px solid `--accent` with a 1px *outer* offset on the header treeitem. The pill itself is never
  focusable.
- **Contrast** (`currentColor` = `--text-1`, computed with the WCAG formula from token hex). The
  dashes sit on the border ring, so the neighbour that matters is the 40% warn border that shows
  in the gaps: **6.0:1 dark** (`#e8eaed` vs ≈`#665628`) / **9.0:1 light** (`#1c1f24` vs
  ≈`#d1bd95`). Against the other neighbours: the pill tint `color-mix(--warning 14%, --bg-1)`
  measures 10.4:1 / 12.9:1, and the outer `--bg-1` measures 13.5:1 / 15.5:1. Every pair clears
  the 3:1 graphics floor.
- **Selector scope is safe.** In §11, `aria-busy` goes on a *row*, never on a warn pill, so no
  submodule or worktree pill can match this selector.
- **Motion: none.** The cue is static, so `prefers-reduced-motion` doesn't change anything. No
  transition on `outline`.
- **Forced colours:** the dashed `currentColor` outline renders as `CanvasText`. No override needed.
- **Density:** sidebar pills don't change with density (§11). Same geometry in `cozy` and `compact`.
- **Both themes:** same rule. The ratios for each theme are listed above.

### 1.4 Decomposition (the P121e leaf pattern stays)

- `src/components/sidebar/SectionRollupBadge.tsx` — add an optional prop
  `refreshing?: boolean` ("a verdict exists and a re-check is in flight"). That is the only new
  prop. The caller builds the right `ariaLabel`/`title` strings, so the badge stays
  status-agnostic. Priority order:
  1. `busy` → hueless `label` pill (unchanged; wins if both flags are set);
  2. `count > 0` → warn pill; when `refreshing`, add `aria-busy="true"`;
  3. otherwise → `null` (whether or not `refreshing` is set).
  Also give the warn pill span **`role="img"`** (§1.5). Update the doc comment's priority list to
  match.
- `src/components/sidebar/TagSyncRollup.tsx` — derives both flags **in the leaf**:
  `busy = state === 'checking'`; `refreshing = useTagSyncChecking() && state !== 'checking'`.
  Don't pass `refreshing` down from `TagsSection`. The context read must stay in this leaf, because
  `TagsSection.recheck.test.tsx:134` pins `tallyRenders('TagsSection') === 1` per re-check.
- `src/components/repoWorkspace/useTagSync.ts` — **no change.**
- `src/components/sidebar/TagsSection.tsx` — **no change.**

### 1.5 Microcopy (with singular forms: the current strings say "1 tags")

| Where | N = 1 | N > 1 |
|---|---|---|
| `aria-label`, settled | `1 tag out of sync on origin` | `N tags out of sync on origin` |
| `title`, settled | `1 tag differs from origin. Expand to resolve.` | `N tags differ from origin. Expand to resolve.` |
| `aria-label`, re-check | `1 tag out of sync on origin, checking again` | `N tags out of sync on origin, checking again` |
| `title`, re-check | `1 tag differs from origin — checking again…` | `N tags differ from origin — checking again…` |

`origin` stands for the report's `remote`. When `remote` is null, the settled/re-check `aria-label`
drops ` on origin`, and the `title` says `the remote` (current behaviour). The re-check state goes
into the **`aria-label`** as well as the title. `aria-busy` on a static `<span>` isn't announced by
any screen reader, and `title` only reaches mouse users (§11: "a pill that carries meaning must
also be in the accessible name"). The pill's inner spans stay `aria-hidden` as today.

**Existing MUST-FIX, fixed in the same pass:** the warn pill puts `aria-label` on a bare `<span>`
with no role, and it renders *outside* the header treeitem (`SectionHeader.tsx:36-47`, `{extra}`
is a sibling of the `<button role="treeitem">`). So its name doesn't fold into the `Tags` treeitem,
and on a generic element it may be dropped entirely. The rollup has probably never been heard by
AT. The fix is the §11 type-as-image rule: `role="img"` on the warn pill span, keeping the
`aria-label`. `⚠ N` is a glyph+count standing for a sentence. The hueless `checking…` pill needs
no role, because its visible word already is its text and `aria-busy` stays on it. §11's
"busy pill drops its title" rule doesn't apply here: that rule covers a pill whose label *is* the
participle, and this pill keeps its verdict label.

### 1.6 Expanded section: nothing else flips (confirmed)

  on the settled `ready` state, `TagsSection.tsx:143-147`).
- `TagSyncOfflineNote` is gated on `tagSyncState === 'unavailable'`, which stays during a re-check.
  It neither disappears nor changes text mid-check, and it's replaced only when the new check
  settles. No retry text is added to it (§2.3 quiet degrade).

### 1.8 Harness

## 2. Activity dock: only this tab's repository

### 2.1 Tab whose repo has no runs, while other repos are busy

**Show no dock at all.** `GitActivityDock` keeps its §3.1 behaviour (`return null` until this
repo's first run of the session), so that tab looks exactly like a fresh session. Don't hint at
other tabs' activity ("2 operations running in other tabs"). That would be new cross-repo chrome
inside a surface that's now scoped to one repo. If it's ever wanted, it belongs on the tab strip
(see §2.4).

- The latch (`everShown`, `GitActivityDock.tsx:84`) must now be driven only by this repo's runs.
  All tabs stay mounted (`App.tsx:411-414`, one `RepoWorkspace` per `repoId`), so filtering is
  enough. **If** a `RepoWorkspace` instance can ever change `repoId` without remounting, the latch,
  `collapsed` and `height` must reset with it. Key the dock on `repoId` if in doubt.
- The existing empty state (`No git activity yet.` / `Every change Bonsai makes to this
  repository shows up here.`, P119-ui §548) is still reachable only after **Clear**. Keep the copy
  unchanged. "this repository" is now literally true.
- `Ctrl/Cmd+Shift+L` in a tab with no dock does nothing, as today. The palette row
  **Git activity** is hidden until this repo has a run (`gitPaletteEntries` `hasGitRuns`, now
  per repo).

### 2.2 Surfaces that showed other repos' runs and must now scope to this repo

These all read `activeRun` / `runs` from `useGitDock` (`src/components/repoWorkspace/useGitDock.ts`).
Once the architect's filter is applied upstream of that hook, none of them need their own code
changes. The tester should assert each one with a run in repo B while tab A is in front:

| # | Surface | Today (leak) | After |
|---|---|---|---|
| a | Toolbar phase readout `ToolbarPhaseReadout` (`WorkspaceToolbar.tsx:226`, fed by `useGitDock.ts:91-99`) | B's `Fetching…` / object counts show in A's toolbar | A's toolbar is silent |
| b | Push button participle (`WorkspaceToolbar.tsx:202`, `gitCategory`) | A's own push could read `Force-pushing…` from B's force-push | A's category only |
| c | Commit box phase readout (`commitPhase` → `CommitBox`) | B's `Committing…` in A's commit box | A's commit runs only |
| d | Dock progress bar + header lead / elapsed (`GitActivityDock.tsx:159-178`, `GitActivityHeader`) | lead summary and bar driven by B's run | A's runs only |
| e | Polite live region (`GitActivityDock.tsx:234`) | the fronted tab announces every repo's phase changes and results | A's runs only |
| f | Clear (enabled state + scope) and palette gating | `hasTerminalRuns` / `hasGitRuns` counted all repos | this repo only. **Clear never removes another repo's runs** |

The once-per-second tick interval (`useGitActivity.ts:243`) now only runs while *this* repo has a
running op. That's a small idle-CPU win for background tabs. Nothing to design there.

### 2.3 What does not change

Dock geometry, collapse/resize, row anatomy, copy, keyboard model, density and both themes stay as
in §12.10 / P119-ui. There are no new strings except the ones in §1.5.

### 2.4 Tab strip

`TabStrip.tsx` has no run indicator today (confirmed), so nothing lit up across repos there and
nothing needs to change. **Follow-up to defer (not in P123):** now that a background repo's
push/fetch isn't visible anywhere from another tab, a small static busy mark on that repo's tab
(glyph + tab `aria-label` suffix ", git operation running", no motion) is the natural next step.
Recommend filing it as a TODO follow-up, not adding it now.

### 2.5 Harness

The mock activity events carry **no `repoId`** today (`src/ipc/mock/gitActivity.ts`). Until the
architect's plumbing lands in the mock, the harness can't show per-repo scoping. Once it does, the
state to check is: two mock repo tabs, a slow run started in B (e.g. the existing long push/fetch
mock) while A is in front. A's dock stays absent (or keeps its own log), A's toolbar and commit box
show no phase, and switching to B shows the run. If the mock can't carry `repoId`, mark this a
**USER CHECKPOINT**: in `pnpm tauri dev`, with two repo tabs, push in one and confirm the other
tab's toolbar/dock stay quiet.

2. **Log lifetime on tab close/reopen** is the architect's call. It only decides whether a
   reopened tab shows its old log or starts with no dock. Either is fine for the UI, since both
