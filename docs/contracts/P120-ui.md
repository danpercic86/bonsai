## 3. Static vs runtime: **static "On Windows"**. Do not call `layoutShiftSupported()` here.

Reasons:
- The block is the fixed consent statement. `devPrivacyCopy.test.tsx` asserts it is
  environment-independent: only the "Right now:" note varies. A capability branch would make the
  privacy text differ by machine, and it would differ in tests too (jsdom has no
  `PerformanceObserver`, so the tests would only ever see the non-Windows branch).
- The browser harness runs Chromium on every OS, so a runtime branch would show the Windows copy on
  a macOS dev machine. That is a true statement about the harness and a false one about the
  shipped app.
- Statically, support maps to platform: Tauri uses WebView2 (Chromium) on Windows and WebKit on
  macOS and Linux. "On Windows" is true for every shipped build, and it is also true to a Windows
  user reading an export from a Mac colleague.
- If WebKit gains the API later, the copy is out of date but it **under**claims, which is the safe
  direction for a privacy surface. Revisit the copy when that happens (follow-up, not a blocker).
- `ui-reference.md` has no convention on naming platforms in copy, and this contract adds none.
