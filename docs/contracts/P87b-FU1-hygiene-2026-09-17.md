## 3. `P87b-FU1-FU4-git-dock-ui.md` F-F(a) — the gate is open, so the flag is now actionable

F-F(a) (`:446-451`) reads: *"the mock call sites pass literal targets … Fix when a detached/unborn mock
fixture exists: derive from the fixture HEAD and pass `null` when there is no branch."*

**That fixture already exists.** `src/ipc/mock/repoState.ts:89` declares
`RepoKind = 'default' | 'detached' | 'unborn'`, selected by `?fixture=detached` or a path substring
(`:229`, `:237`) and covered by `repoState.test.tsx:146-157`. So the conditional is satisfied and the
defect is **live**: `handlers/status.ts:145`, `handlers/stash.ts:148` and `handlers/merge.ts:83` pass
`'main'` unconditionally, and `runMockActivity` emits `started` before the inner body runs, so an
unborn fixture's first commit renders `Commit main` — the exact fact-claiming the run-target §4 guard
exists to prevent.

**The trap that makes the naive fix wrong — record this, it is the §4 lesson replayed on the mock
side.** `repoState.ts:335-336` returns `{ branchName: 'main', oid: '', detached: false, unborn: true }`
for the unborn kind, deliberately mirroring real `read_head_info`. So `head.branchName ?? null` **still
renders `Commit main`** on unborn. The mock needs the same explicit guard as the resolver:

```ts
const target = state.kind === 'unborn' || state.kind === 'detached' ? null : head.branchName;
```

Detached alone would be safe with `?? null` (`repoState.test.tsx:156` shows `branchName: null`); unborn
is not. This is `P87b-FU1-run-target.md` §4's "delete the `unborn ||` half and a repo's **first commit
silently renders `Commit main`**" — one layer over, in TypeScript, with no test currently failing.

**Not raised to MUST.** It is still harness-only fidelity and still low, per the original flag. It
should carry the snippet above and a dated "precondition met 2026-09-17" line so the next reader does
